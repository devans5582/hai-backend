# HAI Ontology Glossary

Ontology 1.0.0, methodology 1.0.0, ruleset 1.0.0. Rebuilt on every change to the manifest.

## Layers And Entities

### Subject

What is being rated.

| Entity | Table | Mutability | Writers | Description |
|---|---|---|---|---|
| Organization | `organizations` | mutable | hai_pipeline, hai_api, hai_admin | The rated organization. External identifiers are stored only when verified against the submitted domain. |
| OrganizationRelation | `organization_relations` | mutable | hai_pipeline, hai_api, hai_admin | Parent, subsidiary, affiliate or acquisition links between organizations. Drives independence. |
| AISystem | `ai_systems` | mutable | hai_pipeline, hai_api, hai_admin | An AI system operated by the organization. Optional in v1 (decision D6); evidence may link to the organization directly. |
| Claim | `claims` | append_only | hai_pipeline, hai_api | An assertion the organization makes about itself. A claim is never evidence of its own truth. Uploads enter as claims. |
| Control | `controls` | mutable | hai_pipeline, hai_api | A governance mechanism protecting a system or the organization. |
| TestOutcome | `test_outcomes` | append_only | hai_pipeline, hai_api | A point-in-time test of a control. A failed test is kept and shown, never dropped. |
| Incident | `incidents` | mutable | hai_pipeline, hai_reviewer, hai_api | One row per real-world event regardless of article count. News reports attach as evidence (AT-04). |
| Remediation | `remediations` | mutable | hai_pipeline, hai_reviewer, hai_api | An action taken to fix an incident. Closure counts as independently verified only with an independent verifier. |

### Evidence

What Humaital found.

| Entity | Table | Mutability | Writers | Description |
|---|---|---|---|---|
| Publisher | `publishers` | mutable | hai_pipeline, hai_admin | Who published a source document. org_id is set when the publisher is the rated organization or an affiliate. |
| Connector | `connectors` | mutable | hai_admin | A configured evidence source. A new source is a configuration row, not an ontology change. |
| ConnectorRun | `connector_runs` | mutable | hai_pipeline | Proof that a fetch was attempted for an assessment and how it ended (IC-16). Recorded even when nothing came back. |
| SourceDocument | `source_documents` | append_only | hai_pipeline, hai_api | A frozen copy of a fetched or uploaded document with its hash, dates and rights. A re-fetch with a different hash is a new row. |
| SourceCluster | `source_clusters` | mutable | hai_pipeline | Groups syndicated or near-duplicate documents so they count once for independence and confidence (IC-09). |
| EvidenceSpan | `evidence_spans` | append_only | hai_pipeline | The citable unit. The exact quote with character offsets into the stored text (IC-03). |
| EvidenceLink | `evidence_links` | mutable | hai_pipeline, hai_engine, hai_reviewer | The only bridge from evidence to a score. One span, one target, one criterion, six separate judgments (spec section 6). |

### Methodology

The rules being applied.

| Entity | Table | Mutability | Writers | Description |
|---|---|---|---|---|
| MethodologyVersion | `methodology_versions` | mutable | hai_admin | A released methodology. Only a signed Humaital change record creates a new version. |
| Pillar | `pillars` | mutable | hai_admin | One of the six pillars. |
| Criterion | `criteria` | mutable | hai_admin | One of the twenty criteria. Codes are permanent; retired codes are never reused. |
| LevelDescriptor | `level_descriptors` | mutable | hai_admin | What each level 1 to 5 means for one criterion, and the maturity rung it requires (decision D1). |
| CriterionApplicability | `criterion_applicability` | mutable | hai_admin | When a criterion does not apply or must be reviewed (decision D5). |
| Rule | `rules` | mutable | hai_admin | One rule of a ruleset, referenced by code so traces can name it. |

### Assessment

The rating itself.

| Entity | Table | Mutability | Writers | Description |
|---|---|---|---|---|
| Assessment | `assessments` | mutable | hai_api, hai_pipeline, hai_engine, hai_reviewer | One scoring run. Pins every version (IC-18). lifecycle_state follows spec section 8.1. |
| EvidenceSnapshot | `evidence_snapshots` | immutable | hai_pipeline | Frozen copy of every link's judgment columns, incident states and version pins. The rules engine reads only this (AT-07). |
| CriterionFinding | `criterion_findings` | append_only | hai_engine | LLM or heuristic output. Advisory only. Rejected findings are stored for audit and never used (IC-05). |
| CriterionDecision | `criterion_decisions` | append_only | hai_engine | Rules-engine output. The only source of criterion levels. Every decision lists the rules that ran (IC-14). |
| PillarScore | `pillar_scores` | append_only | hai_engine | Derived per pillar; never edited. |
| AssessmentResult | `assessment_results` | append_only | hai_engine | The HAI Score, confidence and effectiveness plus the outcome status set only by the rules engine (AT-10). |
| CertificationDecision | `certification_decisions` | append_only | hai_reviewer | Signed by a named reviewer. Never written by the LLM, the engine or the browser (IC-13). |
| Review | `reviews` | append_only | hai_reviewer | A human decision on an incident, contradiction, borderline confidence, finding, link, appeal or certification. Always with a reason. |
| AuditEvent | `audit_events` | immutable | hai_pipeline, hai_engine, hai_reviewer, hai_api, hai_admin | Append-only, hash-chained record of every decision-bearing write (AT-15). |

| Code | Kind | Scope | Order | Description |
|---|---|---|---|---|
| GATE-APPLICABILITY | gate | criterion | 10 | Evaluate the criterion's applicability conditions. not_applicable excludes the criterion; review routes it. |
| GATE-COVERAGE | gate | criterion | 20 | Set coverage state. unavailable only when a connector run failed or was blocked and no admissible support exists (IC-15); otherwise missing, observed, not_tested, failed or contradictory. |
| ADJ-START-FROM-FINDING | adjustment | criterion | 30 | Start the level from the accepted finding's proposed level, or from the evidence ladder when no finding was accepted. Findings are advisory. |
| CAP-NO-ADMISSIBLE-SUPPORT | cap | criterion | 40 | Without any admissible supporting link the level is the missing level. |
| CAP-MATURITY | cap | criterion | 50 | Cap the level at the highest level whose required maturity rung is reached by an admissible supporting link (decision D1). Source tier never sets maturity. |
| CAP-FAILED-EXECUTION | cap | criterion | 60 | A failed test outcome caps the level at the specified_control level. |
| GATE-UNVERIFIED-INCIDENTS | gate | criterion | 70 | Alleged or under-investigation incidents targeting this criterion route it to review with no automatic effect (IC-11). |
| ADJ-INCIDENTS | adjustment | criterion | 80 | Apply each substantiated incident's severity effect once, on its most material criterion only (IC-10). |
| CONF-EVIDENCE | confidence | criterion | 90 | Confidence from admissible supporting links: tier x class x rung credit x materiality x freshness decay x base, clusters counted once (IC-09), plus corroboration, execution and omission terms. |
| CONF-CONTRADICTION | confidence | criterion | 100 | Admissible contradicting links lower confidence and, with admissible support, make the criterion contradictory. |
| CONF-INCIDENT-CEILING | confidence | criterion | 110 | A substantiated incident's confidence ceiling caps the confidence of its most material criterion. |
| CAP-SCORE-CEILING | cap | assessment | 200 | The HAI Score never exceeds scoring.score_cap. |
| CAP-SCORE-LOW-CONFIDENCE | cap | assessment | 210 | When overall confidence is below the threshold the score is capped. |
| GATE-REVIEW-TRIGGERS | gate | assessment | 220 | Collect review triggers: contradictory criteria, unverified incidents, borderline confidence, certification request, second-opinion disagreement. |
| GATE-CERTIFICATION | gate | assessment | 230 | Compare the score and confidence with the threshold in force (decision D3) and record gate reasons. |
| GATE-OUTCOME-STATUS | gate | assessment | 240 | Set outcome status, first match wins: access_limited, insufficient_evidence, governance_baseline, confidence_too_low, certification_not_yet_achieved, hai_certified (only with a signed decision). |
